# 构建内存与部署追踪

音频转换与语音合成会在系统临时目录创建工作目录，文件在运行时生成和清理。原来的动态 `path.join(os.tmpdir(), prefix)` 被 Turbopack 当成项目文件路径分析，构建报告约 169 万项匹配，并把说明、测试、创作资料和大量无关文件列入服务器追踪清单。匹配数量可能重复，不等于实际独立文件数量。

`makeTempDir` 保留原来的路径、随机目录创建和清理方式，仅在临时路径构造与文件系统调用上使用 `turbopackIgnore` 标记。标记位置按[上游说明与修正](https://github.com/vercel/next.js/issues/95125)核对；只标记 `fs.mkdtemp` 的尝试仍产生全项目追踪，已保留失败证据。不能用注释替代实际构建与运行验证，也不要把标记用于需要部署的真实内容文件。

## 本机测量

2026-10-12，Windows / Node.js 24 / Next.js 16.4.0，同一依赖与硬件，构建文件系统缓存保持关闭。以下是实际单次结果，不是跨机器性能承诺，也未控制所有操作系统与类型检查缓存。

| 项目 | 未修正路径构造的对照 | 最终版本 |
| --- | ---: | ---: |
| 总构建耗时 | 261 秒 | 109 秒 |
| 根进程报告的工作集峰值 | 18.31 GB | 2.03 GB |
| 67 份部署清单的引用总数 | 96,110 | 42,110 |
| 全项目动态文件系统警告 | 有 | 无 |
| 说明、测试、创作资料与 README 追踪 | 有 | 无 |

最终采集 113 次进程内存数据，根进程和当时存活的子进程工作集合计最高约 3.06 GB。相加可能重复计算共享页，不能作为独占物理内存；工作集也不是 JavaScript 堆。另一次路径修正后的构建约 90 秒，根进程报告峰值约 1.95 GB。低内存机器、Linux、Docker 与并行构建仍需单独验证。

## 部署边界

生产文件追踪排除说明、测试与创作目录，保留实际公共资源。`npm run check:build-isolation` 拒绝私有数据、开发缓存、作者资料、测试配置和工作区外引用；即使私有目录已被排除，意外追踪整个项目也可能再次带入测试配置，检查仍应失败。

不要把开发目录或 `.next/cache`、`.next/dev` 当作生产包。Windows 的生产外部依赖别名使用目录链接；把这些链接展开成多份库，可能让应用与 Kokoro 载入不同的 Transformers / Tensor 类型。隔离案例实际复现了模型缺少 `style`、`speed` 输入；保留相同依赖身份后，同一模型完成了 7.77 秒 MP3 播放。源文件内容相同也不能保证 JavaScript 模块实例相同。

本轮在不含 `docs`、`tests`、`art` 与站点 `.env` 的独立服务器目录启动编译后的网页，明确提供公共资源、题库、模型与存储，保留清单中的三个项目源文件。依赖链接到本机已安装库，worker 使用单独的源码进程。实际登录、自然语音生成、完整播放和必要磁盘资源的字节校验通过。演练范围为 Windows 部署边界；独立安装、正式 standalone 包、Docker、Linux 与公网验收仍待完成。

当前仍推荐按[部署说明](部署说明.md)在目标目录安装依赖并构建，不直接搬运本机 `.next` 目录。模型和私有数据分别配置，不随源码发布。

## 维护检查

```powershell
npm run build
npm run typecheck
npm run check:build-isolation
npm test
npm run test:e2e
```

升级前执行备份，发布前执行 `npm run check:release`。保留实际失败与成功日志、进程测量和运行报告；它们位于忽略发布的 `data/verification/`，不包含在开源提交中。
