# 录音额度与实测时长

录音时间额度和 AI 现金费用分别记录。时间额度决定可以开展多少练习；AI 请求仍受站点或个人月预算控制，用量页展示实际请求与估算费用。增加分钟券不会提高月预算，也不会给云服务账号充值。

## 从预留到实测

开始练习时先预留本次所需时间。申请上传凭证时，浏览器申报的时长用于暂记；录音上传后，后台通过 FFmpeg 解码，按服务端测得时长核对。核对时使用同一数据库事务更新录音时长与时间账本。

- 实测比申报更长：补扣差额。
- 实测更短：退回多暂记的分钟券部分。
- 仍在进行的练习：保留剩余整题所需预留，退出后释放未用部分。
- 重复上传、解码任务或手动重试：复用同一回答与时间账本，不反复扣除或退款。

例如，无当日基础分钟、拥有 600 秒分钟券时，一段申报 1 秒的录音会先暂记 1 秒；后台实测为 12 秒后，券余额更正为 588 秒。第二天仍为 588 秒。若申报 12 秒、实测 1 秒，多暂记的 11 秒退回。每个会话每天累计时长后向上取整到秒，不对每个音频分片重复取整。

## 为什么显示「等待录音额度」

录音上传后，其实测时长可能超过当时能够覆盖的额度，例如其他练习仍占用预留。已录音频与测量结果保留，尚未覆盖的秒数写入账本，页面显示「等待录音额度」与具体差额。

此时可以回放原录音；新的识别和反馈请求暂不发出，也不自动反复重试。新练习不能开始。可以退出其他未完成练习释放其未用预留，或按当前兑换规则取得分钟券，再点击「核对额度并继续」。仍然不足时返回明确提示，已保存内容继续保留。

未覆盖时长不会因午夜、暂停、刷新或删除单条记录消失。历史录音按其提交日期与原有基础分配核对，下一天的免费基础额度不自动替代前一日缺少的覆盖。新的有效分钟券可以覆盖这些已录时长；覆盖完成后再手动恢复处理。

## 券到期与删除

已预留或已消耗的券有独立账本。更正历史录音时，可以核对录音提交时仍然有效的券；更正不会延长券有效期，已过期余额不会重新供新练习使用。删除单条记录撤销回放和资料访问，已经消耗或尚未覆盖的时间记录继续保留，不能通过删除退回已用分钟。

普通暂停和离线退出的行为见 [练习暂停与额度](练习暂停与额度.md)。尚未上传的片段仍按申报暂记，上传后的实测更正已经验证；异常关闭的残留分片、长期无法补传时的暂记回收仍需进一步完善。

## 中断片段与完成练习

中断片段可以保留、回放和处理，其时长计入真实发生的练习。普通关卡、自由练习和重练的必答位置，需要至少一条完整保存且没有中断标记的回答才能完成；只上传中断片段不能完成关卡，也不能解锁下一关。

中断片段的反馈不计入关卡目标达成；完整重答后再按完整回答核对目标。已经开始的模考继续沿用部分截止时间与完整作答规则，退出仍记录为中断。

## 升级与验证边界

迁移 `0008_measured_quota.sql` 为时间预留记录增加当日基础额度快照、累计使用秒数和未覆盖秒数。升级前完成私密备份，正常迁移并重启网页与 worker，刷新浏览器。原始录音、Key 和现金预算保持现有配置。

新预留保存当时的基础限额。旧版本没有逐日限额历史，升级时从当前可读取的账号或站点配置初始化快照，至少保留原来已经分配的基础部分；不能据此重建管理员曾经设置的每一日额度。

验证包含真实 PostgreSQL、FFmpeg 解码、后台处理函数、并发重试、跨日、到期、删除、基础分钟竞争与旧表升级。页面另使用独立 Next.js/worker 完成上传、等待、4 秒音频回放和手动恢复。声音为合成信号，转写/反馈为模拟服务，这些证据不代表真人口语、手机或教学质量验收。详细资料仅保存在被 Git 忽略的本机目录。
