## 接入百炼

2026-09-28 已在本机配置 `DASHSCOPE_API_KEY`，并切换为 `AI_PROVIDER=dashscope`。真实 ASR 与 LLM 连通检查通过，网页与 worker 已重启。测试使用合成语音，不代表真实口音、噪声或反馈教学质量已验收；下方真机与质量检查仍待完成。未配置密钥的其他安装环境可以继续使用模拟服务。

1. 在本机 `.env` 配置 `AI_PROVIDER=dashscope` 和密钥，保证密钥、服务地址和模型授权属于同一地域。默认地址为中国内地北京。
2. 当前实际启用 `qwen3-asr-flash-2026-02-10` 和 `qwen-plus` 非思考模式，考官仍为本机 Kokoro Emma。2026-09-28 已调用 ASR/LLM 确认本次账户权限可用；如以后调用失败，在控制台核对地域和模型授权。
3. 运行 `npm run check:providers -- --real`。检查会生成一句英语语音，再用其测试转写，同时检查 JSON 输出；结果保存在 `data/provider-check.json`。
4. 该命令已接入应用数据库用量账本，调用前检查后台现有月预算。请先启动数据库并迁移；不会自动增加预算。失败时检查密钥、地域、模型授权、网络和余额，不要把完整密钥贴进日志或聊天。
5. 重启 web 与 worker，检查 `/admin/tts` 当前模型音频已就绪，然后开始实际录音。

ASR 使用音频本身，不向真实识别接口提供参考答案。模拟服务使用参考文本生成演示转写，两者必须分开评价。

连通报告分别记录 `connectivityVerified` 和 `qualityValidated`；合成语音的连通检查不代表真实口音识别质量已验收。Emma 仍使用本机 Kokoro，保持 `TTS_PROVIDER=kokoro`。

真实样本评测：准备本机 JSON 清单，每项为 `{ "id": "accent-01", "file": "accent-01.wav", "reference": "本人核对的原话", "category": "chinese_accent" }`。`file` 相对清单所在目录；分类可用 `clear/chinese_accent/noise/pauses/silence`。只放已同意用于测试的录音。运行 `npm run evaluate:asr -- --real --manifest 清单路径.json`，每个调用计入现有预算，结果保存在 `data/asr-evaluation-时间.json`。程序记录 WER 和延迟，静音先在本机拦截；WER 不是发音分数，文本结果仍需人工回听核对。

接口参数核对依据：[阿里云 ASR 文档](https://help.aliyun.com/zh/model-studio/qwen-asr-api-reference)。服务区域和模型权限以你账户中实际可用项为准。

## 内容与质量

- 正常英语、带口音英语、长停顿、背景噪声、空白录音分别录制样本，检查转写和“无法充分评价”状态。

- 审核题库后才把题目标记为 `approved`。生产设置 `CONTENT_REQUIRE_REVIEW=true`，不可批量把未经审核题目伪装成已审核。
