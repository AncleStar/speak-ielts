## 每轮工作方式

1. 读取本清单和上一轮证据，检查 Git 状态、当前服务及涉及源码。
2. 按风险和用户价值选一组问题，先复现或确认代码路径，再做最小完整修复。
3. 为数据、权限、计费和恢复问题做有意义的回归；涉及界面行为时验证真实页面。
4. 运行适合改动的测试与构建；恢复本机服务，检查健康状态和构建是否对应当前源码。
5. 将去敏后的结论写入本文件或独立轮次记录。详细运行数据保存在被 Git 忽略的 `data/verification/`。
6. 源码发布前运行 `npm run check:release`，确认不包含环境密钥、数据库、真人音频和私人信息；同步 GitHub 后核对远端提交。
7. 清单中的缺口未闭合时保持 goal 进行中。不能以“测试通过”推断真人或真机验收通过。

## 第三轮：2026-10-09 · 文本草稿与本机资料

先用上一版实际生产构建复现：在观点输入后使用浏览器返回/前进，会丢失未保存文本且未弹出离开确认；退出登录后，IndexedDB 中的模拟未上传录音仍然存在。复现只使用新建测试库、测试账号和合成夹具，详细证据不公开。

本轮实现：

- 观点输入、三种表达修改与回想文本增加账号隔离的本机草稿。状态明确区分正在写入、已在本机暂存和仅在内存中；最长可恢复 24 小时，不保存 Key 或音频、不自动调用模型、不包含在服务端备份中。
- 刷新或返回后从历史栏恢复草稿。恢复前读取服务端最新版本，遇到冲突禁止直接覆盖，展示最新表达并要求核对；成功保存或生成后清理对应草稿。待确认提交保留同一重试标识，普通回想恢复不虚构录音时长。
- 首页、面试和管理员入口统一确认当前账号后再显示私有内容；直接打开面试地址也会初始化录音归属。修复录音开始时的存储等待与退出后的异步写入错误处理。
- 退出前提示丢失未上传录音和草稿，服务端退出成功后清理本机录音、分片和文本，通知其他标签页停止麦克风、播放与上传。写入与清理在同一数据库事务检查登录标识，防止旧任务复活资料，也防止延迟清理误删新账号。进一步用延迟登录校验复现通知被跳过的竞争：通知现在先检查本机登录标识，未完成的网络校验不阻挡停止动作，并保留待执行的再次校验。登录初始化同样检查期间的标识变更，不误清新登录的数据；已失效登录不再被离开确认阻挡。
- 删除观点同步清理关联草稿，通知旧标签页关闭编辑，并在本次登录中保留删除标记，禁止旧写入重新暂存。浏览器存储被禁用、额度不足或升级被阻止时给出真实限制，清理失败提示手动清除本站数据。
- 统一新增 Natural 复习卡片与复习队列的应用时间，避免数据库时钟略快时，刚加入“今日复习”的表达被短暂显示为未来复习。增加数据库快 5 秒的回归场景；成长测试夹具也明确使用应用时间，保留排除未来记录的产品判断。

所有新增文本沿用当前终端风格；没有改变登录原速动画、磁盘选择返回位置或恢复被取消的插入/圆环旋转效果。API 与预算沿用站点现有配置。

补充竞争验证使用真实浏览器 MediaRecorder 与虚拟麦克风：挂起旧页面的登录校验、拦住登录页导航，在 Node 侧观测音轨状态，确认退出通知到达后 5 秒内、旧文档销毁前音轨已停止。用例 1/1 通过，避免只凭登录后页面没有录音标识判断停止成功。最后改动后本机资料纯单元 5/5、类型检查与生产构建再次通过。

本轮纯单元与实际 PostgreSQL 集成检查 87/87 通过，类型检查与生产构建通过。浏览器回归新增 8 项，包含浏览器返回/刷新恢复、版本冲突、回想文本时长、双标签页上传取消、存储拒绝、实际 MediaRecorder 停止、容量错误和跨标签页删除。浏览器使用模拟服务、虚拟麦克风、加速计时和独立数据库，不消耗真实模型额度。新增退出用例清理自身遗留的活动会话，保留产品原有并发上限，不通过放宽限额掩盖测试污染。
