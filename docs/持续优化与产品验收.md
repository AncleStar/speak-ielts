## 每轮工作方式

1. 读取本清单和上一轮证据，检查 Git 状态、当前服务及涉及源码。
2. 按风险和用户价值选一组问题，先复现或确认代码路径，再做最小完整修复。
3. 为数据、权限、计费和恢复问题做有意义的回归；涉及界面行为时验证真实页面。
4. 运行适合改动的测试与构建；恢复本机服务，检查健康状态和构建是否对应当前源码。
5. 将去敏后的结论写入本文件或独立轮次记录。详细运行数据保存在被 Git 忽略的 `data/verification/`。
6. 源码发布前运行 `npm run check:release`，确认不包含环境密钥、数据库、真人音频和私人信息；同步 GitHub 后核对远端提交。
7. 清单中的缺口未闭合时保持 goal 进行中。不能以“测试通过”推断真人或真机验收通过。

## 第三轮：2026-10-09 · 文本草稿与本机资料

先用上一版实际生产构建复现：在观点输入后使用浏览器返回/前进，会丢失未保存文本且未弹出离开确认；退出登录后，IndexedDB 中的模拟未上传录音仍然存在。复现只使用新建测试库、测试账号和合成夹具，详细证据不公开。

本轮实现：

- 观点输入、三种表达修改与回想文本增加账号隔离的本机草稿。状态明确区分正在写入、已在本机暂存和仅在内存中；最长可恢复 24 小时，不保存 Key 或音频、不自动调用模型、不包含在服务端备份中。
- 刷新或返回后从历史栏恢复草稿。恢复前读取服务端最新版本，遇到冲突禁止直接覆盖，展示最新表达并要求核对；成功保存或生成后清理对应草稿。待确认提交保留同一重试标识，普通回想恢复不虚构录音时长。
- 首页、面试和管理员入口统一确认当前账号后再显示私有内容；直接打开面试地址也会初始化录音归属。修复录音开始时的存储等待与退出后的异步写入错误处理。
- 退出前提示丢失未上传录音和草稿，服务端退出成功后清理本机录音、分片和文本，通知其他标签页停止麦克风、播放与上传。写入与清理在同一数据库事务检查登录标识，防止旧任务复活资料，也防止延迟清理误删新账号。进一步用延迟登录校验复现通知被跳过的竞争：通知现在先检查本机登录标识，未完成的网络校验不阻挡停止动作，并保留待执行的再次校验。登录初始化同样检查期间的标识变更，不误清新登录的数据；已失效登录不再被离开确认阻挡。
- 删除观点同步清理关联草稿，通知旧标签页关闭编辑，并在本次登录中保留删除标记，禁止旧写入重新暂存。浏览器存储被禁用、额度不足或升级被阻止时给出真实限制，清理失败提示手动清除本站数据。
- 统一新增 Natural 复习卡片与复习队列的应用时间，避免数据库时钟略快时，刚加入“今日复习”的表达被短暂显示为未来复习。增加数据库快 5 秒的回归场景；成长测试夹具也明确使用应用时间，保留排除未来记录的产品判断。

所有新增文本沿用当前终端风格；没有改变登录原速动画、磁盘选择返回位置或恢复被取消的插入/圆环旋转效果。API 与预算沿用站点现有配置。

## 第二十五轮：生产镜像与当前版本 Linux 冷恢复（2026-10-13）

原容器镜像将构建依赖和 npm 下载缓存一起留在运行环境。本轮改为分阶段构建：Docker 专用 standalone 网页输出，另按锁文件安装运行依赖，再复制静态资源、worker、内容、迁移、语音准备与维护工具。本机 Windows 继续使用原有生产输出，不启用 standalone。最终镜像约 1.76 GB，比本轮同源原版约 2.27 GB 减少 22.21%；这是镜像逻辑字节比较，不是电脑已释放的磁盘容量。旧镜像与卷保留供回滚。

npm 下载缓存通过 BuildKit 复用，首次冷下载仍受网络影响，不能把缓存后的构建时间描述为首次安装速度。初次 standalone 候选因未设置输出而构建失败，已修正并保留失败日志。运行依赖使用完整生产安装而非人工删包；Better Auth 的可选 peer 仍带入 Vitest，未宣称所有测试相关包都不存在。实际镜像检查确认开发用内置 PostgreSQL、TypeScript 编译器、源码测试、说明目录、Git 和私有 `.env` 未进入镜像，下载缓存也没有进入最终层；普通网页/worker 用户为 UID 1000。

再次使用当前任务隔离版本在真实 Linux 引擎演练。源录音经过实际 FFmpeg 和 Linux worker 后生成完整备份；之后添加合成费用记录、删除会话/观点/词汇/账号，再导出最新账本与删除日志，停止源应用及数据库。恢复使用独立 PostgreSQL 与独立数据卷，未挂载源卷。最终镜像独立复验关闭保护：私有 API、登录、新练习、worker 和再次备份被拒绝，临时移开文件标记仍不能绕过数据库关闭状态。

按合成检查表核对后，旧登录与旧密码失效、强制首次改密、费用下限补记、预算保留、个人 Key 清空、后来删除重放、观点/词汇/复习保留通过；原录音完整字节 SHA-256 与 128 字节 Range 回放一致，恢复后可以保存新观点并由实际 Linux FFmpeg/worker 完成新上传。核对资料和所有账号均为合成夹具，无新增付费调用；不能代替真实事故的权限、服务商账单核对与真人识别质量。

Linux 专项另外实际终止任务执行连接，后续写入被拒绝；租约释放后已创建的查询也不能写入，非法写入为 0。七个配置专用队列存在，不同配置 worker 在领取任务之前退出。最终镜像的只读自检共 14 项，12 项通过，AI 与声音两项按模拟配置正确提示警告；不把模拟声音当成自然考官听感验收。原始自然语音模型没有修改，既有 Linux 自然合成证据与本轮模拟完整流程分别保留。

补充已有业务环境的协调更新步骤，区分可以并行构建的不可变 Docker 镜像与不能边运行边改写的本机 `.next`，要求暂停、上传/在途核对、停止旧消费者、完整备份、迁移、任务配置核对和启动验证。主服务按同样原则备份与协调重建，保留原 API、月预算、Emma、既定磁盘与欢迎动画；缺失明细的旧账本继续只读保留，不猜测退款。类型检查、Windows 构建、本机自检、源码/构建一致性、发布与远端核对结果保存为本机验收凭据；上一轮 244 项回归和 66 个浏览器用例不冒充本轮重新运行。

已确认 Android 与 iPhone 两种设备可安排，新增 [双端实测步骤](Android与iPhone双端实测.md)，列出可信 HTTPS、权限拒绝及恢复、试听、录音、后台/锁屏、来电、断网、刷新、原速模考和学习闭环。当前均为待测，没有把桌面 Edge 视口模拟标成手机通过。公网 HTTPS、当前容器的自然考官完整设备流程、真实 OSS、20 次真人练习、至少 30 条反馈审核与受邀试用仍未完成，Goal 保持进行。部署操作与证据范围见 [Docker 部署与恢复](Docker部署与恢复.md)。
