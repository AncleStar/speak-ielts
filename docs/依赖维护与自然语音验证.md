# 依赖维护与自然语音验证

更新依赖时应先验证真实本机语音，再检查网页、后台处理和部署包。模拟提示音不覆盖 ONNX 推理、音色数据、分段合成或浏览器音频解码。

## 当前固定版本与覆盖范围

2026-10-11 保留 Transformers.js `3.8.1`、Kokoro.js `1.2.1` 和 ONNX Runtime Node `1.21.0`，保持原模型版本、四种音色和速度配置。`package.json` 明确固定下列传递依赖：

| 依赖 | 固定版本 | 用途与验证 |
| --- | --- | --- |
| sharp | 0.35.5 | Next.js 与 Transformers.js 的图像依赖；检查真实 PNG 解码、WebP 编码、缩放和 Transformers RawImage |
| global-agent | 4.1.3 | ONNX 安装脚本的代理支持；检查实际本机 HTTP 代理和 NO_PROXY 绕过 |
| @esbuild-kit/core-utils 内的 esbuild | 0.25.12 | Drizzle 的旧加载器依赖；检查同步 CJS、异步 ESM 转换以及真实项目 35 张表的迁移生成、重复生成无变更 |

这些覆盖跨越部分上游声明的版本范围，是本项目显式维护的选择；不要将它们描述为上游已经保证的兼容补丁。已在 Windows / Node.js 24 上用隔离安装验证，其他平台、原生库及 Docker 仍需各自验收。图像依赖修复依据见 [sharp 安全公告](https://github.com/lovell/sharp/security/advisories/GHSA-wq5f-xc86-pv6w)，旧工具链问题见 [esbuild 安全公告](https://github.com/evanw/esbuild/security/advisories/GHSA-67mh-4wv8-2f99)。

隔离升级保留推理引擎后，Emma、Isabella、George、Heart 与 Emma 长句五组输出的样本数量和浮点波形 SHA-256 均与旧版一致。ONNX Runtime 1.30.0 候选能生成音频，但输出长度和波形发生变化，本次未采用；运行成功不足以证明听感不变。

## 可重复运行的离线检查

先安装锁定依赖、配置本机 `.env`，并通过 `npm run setup:voice` 准备模型，再运行：

```sh
npm run check:natural-voice
```

命令直接使用应用的 `naturalTts` 实现，不通过云语音服务或后台队列，也不修改 `.env`、个人 API Key 或数据库。检查：

- 四种支持的音色及 `0.8`、`1.2` 两端速度；Emma 使用 `0.95`。
- 长回答确实进入多段合成；输出仍包含应用的句间停顿。
- 模型和音色身份、真实 WAV 容器、单声道 24 kHz、有限样本及非静音输出。
- 空输入、超长连续字符被拒绝；没有模型下载 HTTP 请求。

音频与 `acceptance.json` 写入当前 `DATA_DIR/verification/`，保留在本机，不上传 GitHub。缓存缺失或损坏时检查失败，不自动下载或切换付费语音。诊断禁止的是本进程的 HTTP `fetch`；这不是系统级网络隔离或原生库网络行为认证。

维护时同时运行 `npm audit`、类型检查、全量测试、生产构建和 `npm run check:build-isolation`。更改原生语音依赖时重新核对固定模型、实际网页及 worker 合成播放，再执行源码隐私检查。审计结果是检查当时、当前锁文件和平台的已知告警数量，不保证不存在未知问题。

音频生成和浏览器播放不代替人工听感、真人口音、教学反馈或手机验收。
