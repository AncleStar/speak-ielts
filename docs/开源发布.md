# 开源发布

项目自有代码采用 MIT，第三方内容保留原许可，见根目录 `LICENSE` 和 `THIRD_PARTY_NOTICES.md`。

## 发布内容

发布应用源码、原创题库草稿、数据库迁移、部署配置、公开界面素材、测试代码和文档。真实用户录音、数据库、环境配置、日志、测试截图、模型缓存、备份和 Blender 本地工程均不属于源码发布内容；它们保留在本机，不因开源整理被删除。

不要使用资源管理器直接压缩整个项目文件夹。推荐先运行：

```sh
npm run check:release
npm run export:source
```

导出脚本先核对 Git 候选文件和所有本地引用中的历史 blob，检查凭证格式、机器绝对路径及与本机敏感环境变量完全一致的内容。只输出命中文件与规则，不输出秘密值。导出目录位于被忽略的 `release/speak-source-时间戳/`，包含内容哈希清单，不包含 `.git`、`.env` 或运行数据。

自动检查不等于能够识别所有私人信息。发布者仍应检查拟发布内容和 `SOURCE_MANIFEST.json`。如果曾把真实密钥推送到远端，仅补 `.gitignore` 或删除文件不足以撤回泄露，需要在供应商处撤销密钥并处理 Git 历史。

## 在 GitHub 发布

1. 在 GitHub 创建空仓库，仓库名自行选择。
2. 推荐从导出的干净源码目录初始化 Git，检查将提交的文件，然后提交并推送。不要上传原项目中的 `.git` 和运行数据。
3. 如使用原项目直接提交，先执行 `npm run check:release` 和 `git diff --cached --stat` 检查暂存内容；不要使用强制添加把已忽略的私人文件加入仓库。
4. 公开仓库包含代码，不会自动部署可访问的网页。服务部署见 `部署说明.md`。

本次整理不代替创建远程仓库或执行推送。

## 新安装

本机入口可自动创建随机认证密钥与初始管理员密码，具体值只保存在新生成的 `.env`。手工 / Docker 部署必须自行配置这些值，示例不附带可用的公共管理员密码。自然语音模型需单独执行 `npm run setup:voice` 下载；不会附带作者的模型缓存或百炼 Key。

仓库测试使用明确的 `example.test` 账号、合成音频和模拟服务，这些是测试夹具，不是生产凭证。
