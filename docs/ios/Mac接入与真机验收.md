# 自有 Mac 接入、开发地址与真机工作包

设备登记：iPhone 14 Pro，iOS 26.6.2（用户报告）；Mac 尚未购入。Windows 工程准备可以继续；当前没有已安装的 iOS 构建或原生验收结果。

## Mac 到位后的步骤

1. 登记芯片、内存、存储、macOS 及可用空间，配置本机备份；公开记录不包含序列号、账号和设备 UDID。
2. 按当时的 [Xcode 兼容表](https://developer.apple.com/xcode/system-requirements) 安装适合设备系统的稳定版 Xcode 和 Command Line Tools，打开 Xcode 完成必要的首次设置。
3. 安装与当前锁文件兼容的 Node，复制干净源码；`.env`、数据、Key、录音、证书和个人钥匙串不通过 Git 同步。
4. 执行 `bash scripts/ios/mac-preflight.sh`。脚本只读检查，不购买资源、不安装工具、不接受协议、不输出凭据。
5. 选定 Capacitor 和插件版本后创建独立小样，编译随包资源。原生会话、存储、录音、播放与生命周期按 Port 逐一实现。
6. 用自有 iPhone 安装开发构建。Xcode 的个人设备开发签名和 App Store/TestFlight 分发是不同流程；对外试用再完成相应会员、签名和测试资料。

版本选择要验证当前 iPhone；不能根据框架声明的最低 iOS 就给整个 App 作兼容承诺。[Capacitor 环境说明](https://capacitorjs.com/docs/getting-started/environment-setup)

## 地址与域名的用途

| 环境 | 需要的资源 | 本阶段状态 |
| --- | --- | --- |
| Windows 文档、内存认证实验、合成数据检查 | 当前电脑，不需域名 | 已具备 |
| iPhone Safari 开发基线 | 手机可访问的可信 HTTPS；隔离测试数据 | 方案待执行，不能使用手机自己的 localhost 指代 Windows |
| iOS 原生小样 | 自有 Mac、iPhone、受控开发后端及对应网络配置 | 等 Mac；实际请求方式和 HTTPS 配置需验 |
| 受邀 TestFlight | 可持续访问的 HTTPS 隔离后端、开发者会员、测试账号与说明 | 未准备完成 |
| App Store 正式运行 | 稳定后端、域名/证书、私有存储、备份与支持页面 | 用户允许按需购买域名；名称、预算、发布主体及服务器仍待确定 |

域名采购在用途、后端和发布地区明确后进行，记录首年与续费价格、注册主体和 DNS 管理方式。域名放在用户自己的注册账号下；不把现有私人应用或数据库直接映射到公网。购买、解析、部署和公开访问分别验收。

初期可先采用隔离临时可信 HTTPS 测试；短期地址不作为长期运行承诺。若要求后端也全部在自有设备运行，需另核对公网连通、持续供电、证书、备份和适用的地区要求。
