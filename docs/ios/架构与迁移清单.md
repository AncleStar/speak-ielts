# 架构与迁移清单

建议在 G1 小样后采用独立的移动客户端构建目录，Web 后端继续提供账号、题库、会话、文件、处理任务及账本。当前不向生产认证配置加入 Bearer 插件，也没有开放新的移动 API。

## 核查结果与限制

首次生成静态清单包含 252 个源码文件、32 组 API 路由、46 个 HTTP 方法、3 个 Server Actions 文件、4 个浏览器录音相关文件及 15 个浏览器存储相关文件。精确版本和路径以 [生成清单](generated/source-inventory.json) 为准。

扫描提取直接导入、导出及语法标记，不是完整打包分析；类型消除、动态导入和传递依赖要在移动构建中进一步核查。新增或修改源码后运行 `npm run prepare:ios` 刷新指纹。

## 迁移分工

| 层 | 现有位置 | 处理方式 |
| --- | --- | --- |
| 用户可见 UI | `components/disc`、`thoughts`、`report`、`growth-calendar` | 评估复用 React 展示与动效；替换 Next 路由、网页专用图片/链接和服务端表单调用 |
| 账号表单 | `components/account/settings-forms.tsx`、`app/actions/account.ts` | 移动客户端调用新的账号契约；核心服务与密码验证保留服务端 |
| 奖励与管理 Actions | `app/actions/rewards.ts`、`admin.ts` | 普通用户签到/兑换按需接口化；管理功能继续在 Web |
| Cookie 与登录 | `lib/auth.ts`、`auth-server.ts`、`request-origin.ts` | Web 保持现有保护；新增原生认证入口需独立审查、接入与回归 |
| 录音/播放 | `lib/client/recorder.ts`、`examiner-audio.ts`、播放组件 | 原生录音、音频会话、文件与鉴权播放通过 Port 接入 |
| 本机状态 | `idb.ts`、`private-session.ts`、`recording-owner.ts` | 按账号与登录 epoch 分区；不能依赖标签页或 BroadcastChannel 驱动原生状态 |
| 网络与时钟 | `lib/client/api.ts`、`uploader.ts`、`lib/timing.ts` | 原生网络附加凭据；复用服务端时钟和幂等语义，不复用相对 URL 的同源假设 |
| 会话、授权、删除、费用 | `lib/services`、`quota`、`providers`、`jobs` | 继续在服务器执行；客户端不重新计算授权或替代账本 |
| Node 专用代码 | 数据库、pg-boss、OSS、FFmpeg、Kokoro Node 推理 | 不随 iOS 客户端打包；Emma 首版仍由现有后端提供音频 |

## 原生会话候选方案

在隔离内存库上使用已锁定的 Better Auth 1.7.5 和签名 Bearer 选项验证了会话读取、错误/未签名凭据、双账号、过期/撤销及现有网页来源保护。实验不证明公共移动登录、Keychain、登录限速、首次改密、删除和真实网络已经接入。[官方 Bearer 文档](https://better-auth.com/docs/plugins/bearer)

接入需要单独完成：

1. 登录入口验证邮箱/密码、限速与脱敏；使用原生网络及原生安全存储。
2. 普通移动 API 显式核对经过认证的身份、封禁/删除/改密状态、资源归属和录音授权版本。
3. 服务器对 Cookie 与 Bearer 同时出现的歧义请求拒绝处理；原生网络不附带浏览器 Cookie。
4. 明确过期、撤销和重新认证；当前会话凭据是签名的 opaque session 值，不按 JWT 解析。
5. 原生写入采用受控的认证入口和服务层；不能全局关闭 Origin 校验，不能把客户端伪造的 Origin 当作认证证明。
6. 退出时先在本机失效、清理账号资料并停止异步任务，再尝试服务端撤销；离线撤销的边界应清楚说明。

## 构建与版本

候选客户端交付本地编译资源及真实原生能力，`server.url` 仅用于隔离开发热加载；不把整个运行中的 Next.js 站点作为生产打包方案。[Capacitor 安装要求](https://capacitorjs.com/docs/getting-started)、[配置说明](https://capacitorjs.com/docs/config)

Mac 上锁定 Node、Capacitor、Xcode 和原生插件版本；Windows 保留现有锁文件。移动 API 契约版本独立于网页内部实现，升级不能破坏已经安装的旧客户端；服务端删除、授权版本和预算仍是最终判定来源。
