## 现在可以执行的命令

在项目根目录运行：

```powershell
npm run prepare:ios
npm run check:ios-prep
npm run test:ios-prep
```

`prepare:ios` 只读取源码和题库，生成 `generated/` 清单，以及被 Git 忽略的合成音频测试数据；不读取真实 Key、不修改数据库、不标记题目 approved、不调用付费服务。

`check:ios-prep` 核对工作包、接口来源、题库指纹和候选契约；成功只代表 Windows 准备包一致。`test:ios-prep` 使用内存数据库做认证库兼容实验，并回归现有来源校验，不连接当前业务数据库。

## 交付目录

- [源码清单](generated/source-inventory.json)：源码路径、哈希、直接导入及需要迁移的语法标记。
- [素材证据清单](generated/material-evidence.json)：原协议、模型和来源说明的哈希；最终授权状态仍待审核。
- [题库审核队列](generated/content-review-queue.csv)：全部 140 道题及指纹；[JSON 版本](generated/content-review-queue.json) 标明首批 30 道主问题。
- [人工审核记录模板](人工审核记录.example.csv)：复制到本机私人目录后填写，审核人、录音和私人意见不放进公开仓库。
- [客户端能力类型](../../lib/ios/ports.ts)：录音、存储、认证、网络、播放、时钟和生命周期的候选边界，原生实现尚未提供。
- 合成 WAV 数据：`data/verification/ios-prep-fixtures/`，不是真人语音或教学质量样本。

## 接下来需要的外部条件

Mac 到位后，先按工作包配置并做最小小样；真机测试前选定可信 HTTPS 开发地址。公开 TestFlight 前落实隔离后端、开发者会员、隐私说明、内容审核和审核账号。域名采购结合后端一起决定，域名不能替代服务器运行环境，也不自动授权公开现有私人数据服务。

每个待验项目保持待验状态。状态和证据分别记录，不能根据文件存在、测试替身或静态扫描宣称原生功能、真人质量或苹果审核已通过。
