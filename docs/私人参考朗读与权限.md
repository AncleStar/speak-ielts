# 私人参考朗读与权限

反馈中的参考回答可能依据个人回答生成，因此其朗读也属于该回答的私人资料。共享题目和固定考官用语仍供已登录用户播放，私人参考朗读与具体回答绑定。

## 用户体验

- 所有者可以朗读自己的参考回答，其他普通账号得到 404，未登录得到 401。
- 管理员只有在所有者开启“允许管理员查看回答”后才可读取；撤回后再次请求立即拒绝。管理员音频列表、缺失重试与统计只处理共享题目音频，不显示私人参考文本。
- 首次必须改密的账号不能通过音频接口绕过改密要求读取私人朗读。
- 换音色会生成新的朗读缓存，但回答归属保持不变，跳转地址同样要求权限。
- 私人朗读返回 `Cache-Control: no-store`，通过应用代理读取。即使使用 OSS，也不为这种朗读签发可转交的对象 URL；真实 OSS 网络行为仍需独立验收。
- 删除练习或账号立即禁止访问，后台清理关联缓存和文件；备份后的删除也会在恢复时重放。已经下载或开始播放的字节无法收回。

音频加载失败时，“朗读参考回答”会显示提示并恢复按钮，可稍后重试；报告文字保留。默认 Emma 在本机合成，没有云 API 费用。改用云 TTS 后，按记录分别缓存可能增加首次生成次数，仍受现有站点预算约束，不自动提高额度。

## 升级与旧缓存

升级前保存完整备份，停止网页与 worker 后迁移到 `0009_private_reference_audio`。旧共享缓存无法可靠证明哪些内容来自个人反馈，因此先全部关闭访问；启动时准备共享题目和固定用语，只重新开放这些已明确识别的公共内容。

旧私人朗读无需沿用原地址，用户再次点击按钮即可按该回答重新生成。没有回答归属的旧缓存保持关闭，由每日清理删除；回答、转写、反馈和原始录音不因该缓存清理而删除。新的私人音频以回答外键关联，不与共享音频混用缓存键。

生成和删除并发时，文件发布前重新核对回答；数据库级联删除和文件前缀清理配合处理生成中的写入，避免留下新孤立缓存。文件删除失败会保留数据库事务供重试，不能当成已经清理成功。

不能用缺少私人朗读权限校验的旧应用版本承接升级后的数据库。恢复旧备份仍须使用带此保护、恢复关闭检查和最新迁移的运行时；单纯回退旧镜像会重新引入共享缓存访问缺口。部署与回滚步骤见 [备份恢复与回滚](备份恢复与回滚.md)。

## 已验证范围

2026-10-12 在独立 Linux Docker 测试库复现了旧版另一个账号可读取个性化朗读的情况。新版实际迁移后验证旧缓存关闭、所有者读取、普通账号拒绝、管理员授权与撤回、私人文本不显示在后台，以及真实音色切换后仍保护原地址和新地址。

实际 Edge 完成 Emma 考官播报、原速 Part 1 练习、虚拟麦克风录音上传、报告、录音回放与参考朗读；临时注入音频 503 后提示与重试可用。音频为真实 Linux Kokoro 合成，转写和反馈使用模拟服务，不把这些结果当成人类口语、教学质量或手机真机验收。

200 项单元及 PostgreSQL 检查通过；补充的 13 项真实备份检查验证私人音频关联和字节保留，后来删除的私人音频记录与文件不在恢复实例复活。没有新增付费请求，也没有修改正常业务预算或语音偏好。
